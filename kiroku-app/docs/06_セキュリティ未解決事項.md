# セキュリティ上の未解決事項・限界

「完全に安全」とは言えません。以下は把握している未解決点です。

## 未実装
1. **Windows Hello によるログイン**: 未実装(職員はID+パスワード)。
2. **BitLocker の有効確認**: アプリは検出しません。導入手順書で管理者が確認する運用です。
3. **端末の無操作ロック**: アプリ側の自動ログアウトなし(親機側のセッションは4時間無操作で失効)。離席時はログアウトの運用が必要。
4. **インストーラーの署名**: 未署名のためSmartScreenの警告が出ます。コード署名証明書は有料(年額数千〜数万円規模)の可能性があり、追加費用になるため導入しません。必要なら事前にご相談ください。
5. **かな検索・表記ゆれ**: 未対応。

## 設計上の限界
- **親機の管理者権限を持つ人は鍵を取り出せます**: DB鍵はDPAPI(コンピューター単位)で保護。親機のWindows管理者アカウントを職員で共用しない・BitLockerを有効にする・親機を施錠管理する、が前提です。
- **監査ログの改ざん検出の限界**: 鍵を持つ者が全行を再計算すれば検出できません(外部への保存を禁止しているため、定期バックアップ内の履歴との照合が補助手段)。
- **UDPの自動検出は暗号化されていません**(返すのは親機名と証明書の指紋のみ。個人情報なし)。接続の正当性は、接続コード(HMAC)で確認します。
- **端末トークンは同じパソコンの他のWindowsユーザーにも読めます**(`C:\ProgramData\KirokuApp\device`、DPAPIコンピューター単位)。トークンだけでは記録を見られず、職員のログインが必要です。
- **子機の画面/印刷物**は、職員が持ち出せば保護できません(運用ルール)。
- **接続コードを表示した画面を第三者に見られると**、10分以内に登録申請される恐れがあります(最終的に管理者の承認が必要)。
- **自己署名証明書の有効期限は10年**で、更新手順は未整備(親機再構築時は子機の再登録が必要)。
- **親機が止まると子機は保存できません**(仕様)。入力は画面と暗号化下書きに残りますが、親機が戻るまで他端末には反映されません。
- 同時に大量の端末/職員(数十)を想定した負荷試験はしていません(5台想定)。
- **管理者の追加**は画面にありません(管理者は初期設定の1名)。パスワード紛失は、復旧キーを使う `reset-admin` コマンドで対応します。

## 運用で守るもの
復旧キーの別保管、別媒体バックアップの継続、退職者アカウントの即時無効化、印刷権限は必要な人だけ、Windows Updateの継続、親機の物理管理。

## 外部送信
テレメトリー・自動エラー送信・クラウド・外部AIへの送信コードはありません。ログは例外の型名とエラーコードのみ(氏名・記録内容は出しません)。
ビルド時のみNuGetに接続します(実行時は不要)。

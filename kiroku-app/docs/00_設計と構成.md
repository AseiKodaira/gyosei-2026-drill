# 設計と構成

## 採用構成と理由
| 要素 | 採用 | 理由 |
|---|---|---|
| 言語/基盤 | C# / .NET 8 (LTS) | 指示の第一候補。Windowsサービス・DPAPI・WPFが標準で使える |
| 親機データ | SQLite + **SQLCipher**(AES-256、全体暗号化) | 小規模・サーバー不要。暗号化をDBレベルで実現。**DBファイルの共有はせず**、親機のサービスだけが開く |
| 通信 | HTTPS(TLS)。親機が自己署名証明書を作り、**子機は証明書の指紋でピン留め** | 外部CA不要でオフライン。指紋の一致しない相手には接続しない |
| 端末認証 | 端末トークン(承認時に親機が発行)+職員のID/パスワード(PBKDF2-SHA256 60万回) | 未承認の端末/退職者を個別に遮断 |
| 画面 | WPF(コードのみ) | 指示の候補。XAMLを使わないのはこの開発環境でLinux上の型検査を可能にするため |
| 自動検出 | UDPブロードキャスト(親機名と証明書指紋のみ返す) | 管理者がIPを入力しなくてよい |
| 配布 | Inno Setup | 無償・日本語対応。親機/子機の選択画面とサービス登録を自動化 |

「Webサイト作成禁止」について: 親機の共有サービスは画面(HTML)を持たず、アプリ専用のAPIをLAN内のTLSで話すだけです。ブラウザは使いません。

## データ・鍵の保護
- DB鍵(ランダム256bit)は **Windows DPAPI(コンピューター単位)で包んで** `db.key.protected` に保存。DBと同じ場所に平文鍵は置かない。
- **復旧キー**(英数字40文字)から導出した鍵で、DB鍵をもう一度包んだものを `recovery.wrap` とバックアップに持たせる。親機が全損しても、復旧キーとバックアップがあれば別のパソコンで復元できる。復旧キー本体は保存しない(初期設定時に1回だけ表示)。
- バックアップ: SQLCipherのスナップショット → さらにAES-256-GCMで包む(改ざん検出つき)。
- 操作履歴(監査ログ)はハッシュ連鎖。1行でも書き換え/削除すると「改ざんチェック」で検出。氏名・記録内容は監査ログに入れない。
- 端末の下書き退避(通信断のとき)はDPAPI(ユーザー単位)で暗号化。保存成功で削除。

## 同時編集
各記録・終礼メモに版番号を持たせ、保存時に「自分が読んだ版」と一致しなければ**サーバーが保存を拒否**(競合)。画面は相手の内容を見せ、
「相手の内容を読み込む/自分の内容で上書き(相手の内容は履歴に残る)/(終礼メモのみ)両方を残す」を選ばせる。無警告の上書きは起きない。
更新前の内容・修正者・日時は履歴表に残る。

## knowbe との対応について
この開発では knowbe の画面・仕様書・スクリーンショットは提供されておらず、公開情報の確認も行っていません。
そのため「knowbeと同じ」とは言えません。指示書にある動線(朝: 利用者選択→通所→保存 / 夕: 選択→退所・作業・様子→保存 / 終礼: メモ→保存)に合わせた**独自設計**です。
操作感を寄せたい箇所があれば、現行の画面のスクリーンショットをいただければ調整できます。第三者のコード・画像は使っていません。

## 利用者の氏名について
同姓同名は内部IDで区別します。氏名の完全一致(空白・全角半角を無視)がある場合は、保存時に確認ダイアログを出します。
かな検索(「やまだ」で「山田」を探す)は未対応です(漢字で一部入力すれば検索できます)。

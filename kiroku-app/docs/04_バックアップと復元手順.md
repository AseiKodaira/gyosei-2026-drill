# 管理者向け バックアップ・復元手順

## 仕組み
- 毎日19時以降に自動でバックアップ(暗号化・検証つき)を作成。親機内に30世代、別媒体に60世代保持。
- **親機の同じディスクだけにあるバックアップは「安全なバックアップ」とみなしません。** 別媒体の設定がないと、バックアップ画面に赤い警告が出続けます。
- 別媒体が外れている/容量不足/3日以上更新なし → 画面に警告。

## 毎週・毎月
- 週1: 「管理」→「バックアップ」で警告が出ていないこと、「別媒体の最新」が新しいこと。別媒体を持ち出して保管する場合は2本を交互に。
- 月1: 「バックアップを確認」→ 全件「正常」。

## 復元試験(年1回以上・推奨は半年ごと。導入時にも必須)
1. 別のWindowsパソコンに親機としてインストール(まだ初期設定はしない)。
2. 別媒体のバックアップファイル(`kiroku-*.krbk`)を用意し、そのパソコンで管理者のコマンドを開く。
3. `"C:\Program Files\KirokuApp\server\Kiroku.Server.exe" restore "E:\kiroku-20260101-190000.krbk"`
   → **復旧キー**を入力。「復元しました」と出ること。
4. `sc.exe start KirokuServer` → アプリを開いて職員でログインし、直近の記録・終礼メモが見えること。
5. 試験用パソコンのデータを削除(個人情報が残るため。アンインストール後 `C:\ProgramData\KirokuApp` を削除)。
結果を日付つきで記録してください。

## 実際に復元するとき(同じ親機で、記録を取り戻したい)
管理画面「バックアップ」→ 一覧から復元したい世代を選ぶ → 「選んだバックアップから復元」→ 復旧キー入力。
復元前の状態は自動でバックアップされ、全員がログアウトされます。

## 親機が壊れたとき
新しいパソコンに親機をインストール → 上の `restore` コマンドで別媒体から復元 → 子機は**そのまま使えません**(新しい親機は別の証明書になるため)。
各子機で「接続設定をやり直す」(子機のアプリ起動時に出る選択肢)→ 新しい接続コードで再登録してください。

## 復旧キーをなくした場合
バックアップは開けません。親機が動いているうちに、管理画面「復旧キーを再発行」を実行し、新しいキーを保管してください(再発行後に新しいバックアップを作ります。古いバックアップは古いキーでしか開けません)。

## 容量不足
画面に「空き容量が足りません」と出たら、不要なファイルを消すか、別のドライブ/媒体を使ってください。

## クリップボード(knowbe転記用コピー)の運用設定【管理者・全PCで実施】
コピー機能はWindows標準のクリップボードだけを使い、外部へ送信せず、内容をログに残しません。アプリは履歴・同期の対象外になる印を付けますが、
**Windows側の設定でも無効にしてください**(他のアプリは従来どおりクリップボードを読めるため、秘密保持を保証するものではありません)。
- 設定 → システム → クリップボード →「クリップボードの履歴」を **オフ**、「デバイス間で同期」を **オフ**
- 組織で一括設定する場合: グループポリシー「クリップボード履歴を許可する」「クリップボードをデバイス間で同期する」を無効
- 画面共有・リモート操作ソフトのクリップボード共有も無効に
- 貼り付け後、knowbe以外のアプリに同じ内容を貼らない
